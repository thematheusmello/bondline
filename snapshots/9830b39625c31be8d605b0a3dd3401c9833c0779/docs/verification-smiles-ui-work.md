## Implemented contract

`CommandExecutor::prepare_ui_smiles(&CaptureStamp, close_epoch:u64,
SmilesRecordInspect)` returns opaque, noncloneable `UiSmilesWork`. Its typed parameters
permit exactly the existing `smiles.record.inspect`; no arbitrary native command or new
wire/registry entry is added. The work retains its originating SharedEngine privately.

Preparation holds that Engine mutex while checking close state, exact close epoch and
full weak source stamp, then reserving the existing two-worker permit and calling Core
prepare. A committed close refuses as `close_committed`; other non-Open/changed-close
contexts refuse as `ui_stale_request`; foreign/replaced source and stale expected revision
refuse as `stale_revision`. Existing wrong-kind, positive ordinal and missing-record
errors remain authoritative. Failed preparation releases any acquired permit.

Preparation releases the Engine guard before returning. `UiSmilesWork::complete_blocking`
uses the unchanged registered completion helper: selected parsing is off-lock, finish
uses the captured origin, cancellation and historical-query semantics stay in Core, and
the permit survives through finish/drop. A clone of the executor shares its original
pool; no new pool or Save reservation is created. Existing SDF/capture/file APIs were
not generalized or refactored. Removing only the new wrapper/method/import/export
reconstructs both original production files byte-for-byte.

The UI caller must still own pending intent and the actual worker through delivery and
thread retirement, reject stale source/close/request results, and clear readonly text on
hide/Open/close. This wrapper is not UI rendering, a close acknowledgement or permission
to bypass those host barriers. A successful historical query never installs source.

## Three independent cases

The original49-byte source has three records, mixed endings, ignored non-UTF8 text and
opaque NUL/non-UTF8 application data. Record2 is exactly `[13CH3][OH]`, on physical line4,
with2 atoms/1 bond and global full21..43, notation21..32, separator32..33, data33..42 and
LF42..43 spans. These are literal independent expectations reused from the existing
query contract, not values generated by a writer or a second parser.

1. Native preparation is active before spawning, visible through executor clones and
   releases its Engine guard. Actual background-thread completion returns all12 literal
   selected fields, discloses no application data/notation through Debug, and preserves
   complete source/history/file state. A second accepted query still returns its captured
   record after the original path is deleted and another complete file is opened; the
   replacement source and current close state are not overwritten. Existing lower-layer
   Weak-owner tests separately establish ownership/release; this case tests actual bridge
   routing and historical preservation.
2. Foreign source with equal bytes, stale params, zero/missing ordinal, identical-source
   Open, close Request/Cancel ABA, non-Open/committed close and Drawing content refuse
   with exact codes and unchanged state. Rejected/dropped work leaves no active slot.
3. An outstanding native capture plus native SMILES query saturate the same two slots;
   both clone and ordinary registry work report busy. Pre-cancel and drops restore capacity.
   Query succeeds while a real whole-SMILES Save owns its reservation and cannot release
   that Save's lease. Actual saved/input49-byte files remain exact. A query neither changes
   a claimed native File request nor binds as File work, and cannot fabricate trusted
   success acknowledgement.

These tests use real command/file work and temporary paths, without an OS window. They
add no new chemistry/oracle claim: the existing independent raw/notation consumers and
SMILES syntax/H/layout limitations stay unchanged.
