## Six prepared acceptance cases

1. Actual app frame loads, decodes, uploads and paints the complete registered image,
   with both record/functional-label regions, correct panel roles and no drag/hover atom
   or bond authority. The entire authored state and original bytes remain exact.
2. Field-only source edits, Undo, Redo and identical-byte Open invalidate the full key.
   Old ready pixels/error/hits disappear immediately; valid SDF history remains usable.
3. Logical resize, origin relocation and DPI2/DPI4 invalidate the cache, even when capped
   device dimensions are identical. One uniform cap preserves aspect within rounding,
   and both axes stay at most2048.
4. The same800×800 device image can be readable at800 logical units and unreadable at400.
   The actual same-graph main-label metric is checked in logical coordinates, not simply
   device pixels or optimistic A4 assumptions. Subscript em is a separate metric.
5. Queued real success and a deliberately corrupted real PNG cannot install after a source
   change. A current decode error is keyed, retires the job, and disappears on new source.
6. Request/Cancel/Request close epochs with a real decoded result already queued keep the
   native frame's finalization blocked until the worker actually exits and retires. Late
   images stay unpainted. Already ready/error/hits clear as required.

Controlled gates carry actual registered results and use finite channel timeouts. Gate
Drop releases a waiting worker; fixture cleanup cancels and joins remaining work outside
any UI frame. No positive pixel result is fabricated. Lifecycle tests first obtain a real
ready view key, avoiding false stale-source success caused only by a guessed viewport.
