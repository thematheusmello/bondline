# Parity target and research method

The user's 2026-11-13 clarification explicitly authorizes reverse engineering and calls for
one-to-one screens, buttons, icon roles, flows and functionality. The previous prohibition
on program-binary inspection is superseded. The complete Professional desktop target,
original Rust implementation, Bondline branding, offline operation, command architecture,
source preservation, independent verification and strict shipped-license policy remain.
The current independent-bond workflow is an implementation increment, not a smaller target
or approval of the final application's design.

Use public official guides, screens, videos, feature charts and demos, then authorized local
artifacts/runtime when those answer missing questions. Do not confuse a Signals cloud screen
with a Professional desktop screen. Record version, platform and tier for each observation;
unknown versions remain unknown. A marketing capability list does not establish UI behavior.

For each reference screen/state, record:

- Stable screen/control IDs and functional roles, layout, visible states and icon appearance.
- Exact source URL and review date; video timestamp, or local artifact version/hash and REA
  Evidence identity. Cache research-only media under ignored .cache/ or target/.
- Entry action, complete interaction sequence, resulting authored state and saved/reopened
  behavior where applicable. Distinguish observation from inference and untested transitions.
- Bondline command, implementation location, tests, native evidence and remaining differences.

Reconstruct familiar layouts and original vector assets from those records. Keep reference
artifacts separate from redistributable product assets. Shipped code/assets still need
MIT/Apache-2.0/BSD-compatible provenance; language choice alone does not establish that.
Licensed runtime access uses existing legitimate entitlements. If a download or observation
is gated, record that boundary and continue public evidence rather than inventing behavior.

Priorities after the current drawing checkpoint: establish a versioned desktop workspace,
menu/palette/dialog/icon and flow inventory; map it to the existing feature checklist;
implement complete creation/editing/persistence workflows through the same registry. Keep
click creation, existing-atom attachment, snapping, order changes and full atom-label behavior
visible while extending the initial bond tool. Verify actual native workflows and independent
file consumers; no menu, screenshot, static analysis or green build alone establishes parity.

Use REA for packaged/runtime evidence; ordinary repository analysis does not need REA.
The original three engineering references are retained as pinned local source checkouts,
with their approaches and license differences recorded separately from product evidence.
No push, publication, agreement acceptance or account creation is implied by this research.
