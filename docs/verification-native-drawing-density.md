## Delivered shared path and unchanged authority

`PageView::at_display_scale(density,origin_phase)` is a geometry-only view copy. It
validates native parameters/composition as `InvalidView`, derives destination
`ceil(logical_size*density+phase)`, and retains the existing100000 source/destination
and coordinate bounds (`InvalidViewport`). The private physical transform is shared
with `at_pixel_size`; the latter retains its2048 readback validation, error order,
min-ratio density/centered padding and identity/composition contract.1×/phase0 clones
the original viewport/projection, including large native vector destinations.
No full physical frame is allocated by view construction or graph projection.

Root's thin `Engine::drawing_scene_with_view` delegates to the existing source-qualified
IO display adapter. The old logical `drawing_view_scene` delegates through that helper.
Native Drawing obtains the current effective egui DPI, preserving its logical camera
and100% convention. Non1× generation uses the exact density and the fractional part
of `canvas_min*density`; painting starts at `floor(canvas_min*density)/density`.
Consequently the physical scene is aligned to the global device lattice without
snapping the canvas or changing the authored page.1× native rendering retains its
legacy route, including its unchanged fractional-origin behavior.

All three graph acquisition/reacquisition sites use the same view; all four hit sites
map logical input into physical coordinates with five-logical-unit tolerance scaled
once. Rectangles, strokes, hover and drag previews map back into egui float coordinates;
fresh glyph pixels are not enlarged logical bitmaps. Atom anchors, raw press/jitter,
foreground/focus/modal/source/revision/view guards and history ordering remain separate.
Existing context invalidation already includes logical dimensions/origin and DPI.

Both the existing physical8..256-em limit and actual main-label `em/density` within
8..256 logical units apply; absent labels do not cause a new error. Higher DPI cannot
make logically tiny text acceptable. Existing4096 primitive/hit limits, source/ink/
visibility/overlap guards and cancellation remain. Higher physical density can still
honestly refuse those bounds; this is not a hard CPU/RSS or responsiveness guarantee.

The existing complete Drawing owner, MOL display-H policy and incomplete-source/wrong-
kind refusals remain behind IO. No source/model/IDs/H/dirty/saved/history/path/close or
Save-acknowledgment authority is added. No new registry command, deferred worker or
native texture cache is introduced. SDF's registered read-only texture workflow and
legacy Fit/current-view distinction are unchanged; SMILES files gain no Drawing preview.
No codec, dependency/lock, font, shader, old oracle/fixture/assertion or approved golden
was changed by these three product paths.
