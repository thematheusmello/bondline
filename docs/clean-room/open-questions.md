# Open questions

- Registry Save currently retains authoring Undo/Redo and records a separate saved baseline.
  G25 printed14 describes only actions since the last save. Exact26.1 history-across-save
  behavior needs evidence; keep this explicit gap rather than claiming full File parity.

- Public 26.1 release notes are available, but no full public 26.1 menu/palette reference
  was located. The 573-row cited baseline in parity-checklist.md covers explicit guide
  controls and shortcut tables plus 26.x desktop deltas; remaining context menus, unnamed
  glyphs and platform-specific controls prevent a complete modern-inventory claim.
- G25 atom table p.68 assigns k to potassium, while p.69 assigns k to sprouting sulfonyl.
  Do not invent precedence. Bond table p.73 and the explicitly modified table p.75 assign
  4 to ring fusion, while the legacy drawing paragraph p.86 describes quadruple-bond input.
  The modified table is positive evidence for its stated default; modern context/default
  differences still need documentation. Example-only bond v at p.74 is not defined in its table.
- G25 uses Color/Colors, Actual/Actual size and Show Document/Fit to window inconsistently.
  Shortcut action labels do not establish exact modern submenu nesting. Most key tables
  use CTRL without a general macOS mapping; only explicitly documented Mac bindings and
  independently verified Bondline behavior may be claimed. Keyboard-layout behavior needs tests.
- Several attachment-point and BioDraw glyphs share labels in the public guide. Their
  exact palette variants remain unresolved. Authorized toolbar/hotkey resources and runtime
  observation may now help under the updated AGENTS policy; record version/hash/evidence
  instead of guessing from memory. No such desktop artifact evidence is established yet.
- The official download center now has controlled-browser evidence of an authentication
  screen, not a public installer link. No reference desktop artifact was acquired or run.
  The public Walnut playlist's entry and first promotional slide were observed; it is a
  Signals web demo with no desktop build identity. Neither observation establishes 26.1
  desktop design or chemical editing behavior. See [the evidence record](../research/official-ui-evidence.md).
- The archived CDX SDK does not establish every modern extension. Preserve unknown data.
- The archived properties/id.htm link returns 404, but CDX-IDENTITY/CDX-OBJECT-ID now establish
  32-bit IDs, zero as unassigned and per-container identity. Older object tables label IDs
  UINT16; the implementation follows the agreeing record/data-type descriptions. Shared-
  container reference precedence is documented; general cross-container ties and modern
  extensions still need evidence. The existing geometry view remains string-based and
  deliberately narrower than complete identity mapping. Exact numeric helpers are delivered.
- Integral-property exponent notation and non-integral numeric-ID spellings have no complete
  grammar in the reviewed archive. Helpers reject these; the syntax layer preserves them.
- The elemental reader now supports fragments under pages/nested groups, with local
  source-reference resolution. Cross-fragment nearest/tied references, alternative groups
  and nested nickname fragments remain unsupported. Other object/reference classes are
  still opaque; no full file-wide semantic validation is claimed.
- The Node guide permits text-only writers while individual property pages define metadata
  defaults. Complete label/metadata interpretation still needs implementation/evidence.
  The elemental view rejects text-labeled nodes without explicit Element metadata; it
  never silently converts a label-only nitrogen into carbon. Explicit metadata is projected,
  but labels/styles/stereo and other unmodelled data remain only in the retained source.
- Absent-position generation and dependent label/bounding box updates still need complete
  mapping/command behavior. The older Geometry utility keeps its direct-fragment scope and
  never presents a p-only patch as a complete atom move.
- Native declared license closure and hosted window smokes pass all three desktop targets.
  Interactive Windows/Linux workflows and complete release notice assembly remain; every
  dependency upgrade needs new closure/source/asset evidence. Crate labels alone are insufficient.
- windows-permissions 0.2.4 declares MIT and author Daniel Dulaney in its exact published Cargo
  metadata, but its archive and reviewed upstream tree contain no LICENSE file. Retain those
  facts/pins in native-file-io.md; resolve release notice/source audit without inventing a notice.
- New Windows ReplaceFile/ACL behavior is source-checked, not natively executed yet. Mac inherited
  allow ACLs and Windows backup directories have a create-to-tighten pre-opened-handle boundary;
  current code cannot revoke such a handle. See native-file-io.md; do not claim universal
  temporary confidentiality. Explicit overwrite checks are not external compare-and-swap.
- One original single-bond scene now has explicit human approval and an exact CPU/GPU/Pillow
  regression. Broader scenes, smooth text, imported styles and platform raster behavior remain
  open; that approval does not establish final UI design or general rendering correctness.
- Editable Office embedding and modern naming/prediction behavior need public evidence.
